The wanted ClaudeCTRL session card is essentially a compressed, UI-friendly version of the raw Claude terminal output. The main differences I notice are:

Actual file edits are preserved.
Raw:
Update(apps\server\src\managers\tasks.ts) + Added 2 lines, removed 2 lines
Wanted: same thing. This is useful progress information.
The actual diff is removed.
The terminal shows individual - and + source lines. The card only says the file was updated and how many lines changed.

Claude's narration is preserved.
Things like:

"Now let's update the prompt..."
"Good — dbRowToTask is the single source of truth..."

remain visible. So you don't want just tool activity; you want Claude's reasoning/status narration too.

Read operations are preserved but simplified.
Raw:
Read 1 file (ctrl+o to expand)
Wanted:
Read 1 file

Terminal-specific interaction hints disappear.

Bash commands become just Bashing.
This is probably the biggest transformation. Instead of dumping:
Bash(cd C:/Users/... && npm test...)
and its output, the card simply displays:
● Bashing
That prevents massive command/output blocks from taking over the card.
Bash results are mostly suppressed, but Claude's interpretation remains. For example, rather than showing all test output, you retain Claude's subsequent:
All 13 tests pass and both packages typecheck clean.
That's much more useful to a person watching the session.
The final response is preserved essentially in full.
The Summary of changes, numbered items, queue explanation, timing, and recap all remain.

So I would define the desired behavior as:

ClaudeCTRL should display Claude's conversational/status text + compact tool activity, while stripping the noisy internals of tool execution.

The rough transformation rules are:

Update(...) → keep filename/path + added/removed count
actual diff → hide
Read N files (ctrl+o...) → Read N files
Bash(command) → Bashing
bash stdout/stderr → hide
Claude narration → keep
final summary/result → keep
terminal UI hints like ctrl+o to expand → hide
timing/recap → currently kept in your wanted example

One subtle point: this is not really summarization. You don't want ClaudeCTRL generating its own condensed version. You want a deterministic parser/filter over Claude CLI output, preserving Claude's words while collapsing tool noise. That distinction matters for how you should implement it.
